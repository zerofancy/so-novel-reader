Gradle 钥匙圈签名

Release 签名使用 Gradle Keyring 0.2 读取系统钥匙圈中的 keystore 密码与私钥密码。 接入方式参考 fcitx5-android 的签名提交。

1. 配置 keystore

使用你自己的 Release keystore，保存在仓库外并备份。此接入不会创建或替换签名身份。

在根目录已被 Git 忽略的 local.properties 中保留原有 SDK 配置，加入以下内容，填写实际文件绝对路径和私钥别名。初始化完成前保持开关关闭：

keyringSigning=false
keyringStoreFile=/absolute/path/to/release.jks
keyringKeyAlias=your-key-alias

路径和别名也可通过同名 -P 参数提供；项目属性优先于 local.properties。路径支持相对项目根目录，但不会展开 ~；Windows 路径建议使用正斜杠。

2. 初始化钥匙圈密码

在已登录桌面、钥匙圈已解锁的本机终端执行：

./scripts/init-keyring-signing.sh

脚本隐藏输入两个密码。私钥密码留空表示沿用 keystore 密码。密码通过短期环境变量交给插件，不写入项目文件或命令行参数。两个密码保存成功后，把 local.properties 中的开关改为 keyringSigning=true。

Windows 或需要单独更新某个密码时，可直接运行插件任务，从标准输入录入密码（Windows 使用 gradlew.bat）：

./gradlew --no-daemon --no-configuration-cache --console=plain -PkeyringSigning=false :setSecretValue --name=android_store_password
./gradlew --no-daemon --no-configuration-cache --console=plain -PkeyringSigning=false :setSecretValue --name=android_key_password

macOS 使用登录钥匙串；Linux 需要会话 D-Bus 和 Secret Service 等兼容服务。首次访问可能提示授权或解锁。

3. 验证并构建 Release

# 检查 keystore、两个密码、私钥别名和证书链，不编译 APK
./gradlew --no-configuration-cache :app:verifyReleaseSigning

# 构建签名 APK
./gradlew --no-configuration-cache :app:assembleRelease

# 构建签名 AAB
./gradlew --no-configuration-cache :app:bundleRelease

也可让本机开关保持关闭，构建时用 -PkeyringSigning=true 临时启用。APK 输出位于 app/build/outputs/apk/release/，AAB 位于 app/build/outputs/bundle/release/。

本项目默认开启 Gradle 配置缓存。启用钥匙圈签名时，包括 IDE 同步在内的配置阶段会读取密码，因此必须关闭配置缓存；代码会在读取密码前拒绝缓存请求。常规命令添加 --no-configuration-cache，IDE 使用临时的 -PkeyringSigning=false 或在本机 Gradle 配置中关闭缓存。

需要固定启用时，在 local.properties 中设置 keyringSigning=true，并在本机 ~/.gradle/gradle.properties 中加入：

org.gradle.configuration-cache=false

如果设置了 GRADLE_USER_HOME，则修改该目录下的 gradle.properties。用户级配置优先于仓库配置，影响本机该 Gradle 用户的所有项目；命令行参数仍可覆盖。配置完成后，IDE 同步和以下构建命令无需临时签名或缓存参数：

./gradlew :app:verifyReleaseSigning :app:assembleRelease

凭据映射与行为

钥匙圈秘密名Gradle 项目属性环境变量
android_store_passwordsignStorePasswordSIGN_STORE_PASSWORD
android_key_passwordsignKeyPasswordSIGN_KEY_PASSWORD

插件读取顺序为项目属性、环境变量、系统钥匙圈。CI 可直接注入上述环境变量，并提供路径、别名和开关；无需桌面钥匙圈。不要把密码写入受 Git 跟踪的文件或 -P 命令行参数。

本项目钥匙圈服务名为 Gradle Project So Novel Reader，与 fcitx5-android 的凭据相互独立；更改根项目名后需要重新初始化。

keyringSigning 未配置或为 false 时不读取签名秘密，Release 保持未签名，Debug 使用默认调试签名；启用后缺少文件、别名或密码会直接失败。

管理或初始化凭据时使用 -PkeyringSigning=false --no-configuration-cache。可用以下命令只查看配置名：

./gradlew --no-configuration-cache -PkeyringSigning=false :listSecretConfigs

不要运行 listSecretValues，它会输出密码。keystore 和密码都需要保留备份。
