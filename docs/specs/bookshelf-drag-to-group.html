1. 目标与本版范围

让书架首页的整理操作直接在卡片之间完成，减少「更多 → 移动到分组 → 选择目标」的步骤。本文的「分类」对应当前界面的「分组」及数据库的 categories，是同一个概念；现有菜单文案暂不统一改名。

本版范围：本版拖拽仅发生在「我的书架」首页，拖动源为未分组书籍，目标为已有分组卡片或另一本未分组书籍。分组详情页仍通过现有菜单移动书籍。已按此首版范围实现。
  • 支持单本书长按拖动、目标高亮、松手提交、边缘自动滚动、取消与失败反馈。
  • 沿用单层分类、一本书最多属于一个分类的规则；不复制书籍，不新增嵌套分类。
  • 本版不包含卡片自由排序、分类拖动、批量拖动、跨页面拖动、悬停打开分类及跨应用拖入。
  • 分组详情页的书籍长按菜单、移动到分组、移回书架顶层以及重命名、删除分组功能继续保留。

2. 手势与视觉反馈

2.1 开始拖动

  1. 在首页书籍的封面、标题或作者区域按住，达到系统长按阈值后进入拖动准备态；给出一次轻触觉反馈和浮起效果。
  2. 长按前的纵向移动超过系统触摸容差时，按正常书架滚动处理。进入准备态后，移动超过容差开始拖动；手指未移动就松开，仅结束准备态，不打开书籍、不弹菜单、不修改分类。
  3. 拖动中显示书籍卡片的浮层预览，保持手指相对卡片的抓取位置；源卡片保留占位并降低透明度，其他条目不因悬停而重新排列。
  4. 首页书籍原有的长按弹菜单改为长按拖动；右上角「更多」按钮仍打开原菜单。点按书籍仍进入阅读，点按分类仍进入详情页。分类卡片的长按菜单保留。
  5. 「更多」按钮独立消费手势，从按钮上开始按住不发起拖动。菜单、对话框、导入遮罩显示时，以及已有拖放写入未结束时，禁止开启新的拖动。

2.2 目标判定

以当前手指位置命中目标，使用目标卡片封面或文件夹主体的可见矩形区域；标题、卡片间空白和源卡片不参与命中。目标右上角菜单按钮不作为有效落点。裁剪区域与被顶栏、底部导航、导入按钮等覆盖的区域均不可命中。

当前目标悬停反馈松手结果
已有分组文件夹主体描边高亮，显示「移入『分组名』」将源书籍移入该分组
另一书籍目标封面描边高亮，显示「与『书名』创建分类」新建未命名分类，两本书一同移入
自身 / 空白 / 页面控件无目标高亮取消，原数据不变
「新建分组」占位卡片无目标高亮取消；此卡片仍仅支持点按新建

同一时刻最多一个目标高亮。悬停立即反馈，不设额外停留时长，也不打开分类或命名框；松手时重新命中并校验，以最后落点为准。长书名和分类名可省略显示，但不得遮住目标。

2.3 滚动、取消与中断

  • 拖动时手指进入网格可见区域顶部或底部的 48dp 边缘带，触发该方向自动滚动，越靠边速度越快，建议最高 600dp/s；到达边界停止。参数可经设备体验调整。
  • 自动滚动期间持续按当前布局重算命中区域；边缘带本身不覆盖落点判定，因此顶部的分类仍可接收书籍。浮层不受网格裁剪，且不拦截命中。
  • 松手落在无效区域时，立即停止自动滚动并清除目标高亮；书籍浮层用约 280ms 的缓动动画回到原卡片位置，同时恢复原大小，再与原卡片衔接，期间不写库。如果原卡片已滚出屏幕，先平滑恢复拖动开始时的书架视野，再完成回位。回位期间屏蔽新的网格操作，避免再次拖动或误开书。收到手势取消、按返回、应用切到后台、配置变化或离开书架时则直接清理拖动状态。
  • 第二根手指加入即取消本次拖动，避免多指造成误提交。取消后的松手不得触发书籍点击。
  • 拖动中若书籍或分组列表发生变化，取消拖动并等待列表稳定；由滚动引起的可见条目变化不视为数据变更。卡片重组不应自行结束拖动。

2.4 提交结果

有效松手后关闭拖动浮层，进入提交态；列表由数据库 Flow 刷新，不提前隐藏书籍或添加临时分类。提交期间屏蔽首页新的整理操作并显示轻量忙碌反馈，防止重复移动。

  • 移入成功：显示「已移入『分组名』」；顶层移除源书籍，分组数量加一。
  • 合并成功：显示「已创建『实际分类名』，并移入 2 本书」；顶层移除两本书，出现数量为 2 的新分类。
  • 成功后停留首页，不自动进入新分类、不弹命名框；可通过原有入口重命名。保持当前滚动位置，条目减少时仅做必要的边界收敛。
  • 失败：提示「整理失败，请重试」，恢复可操作状态。目标已失效时提示「书籍或分类已变化，请重新拖动」。全部失败路径均不得遗留空的新分类或只移动其中一本。
  • 提交已发出后不提供手势撤回；页面离开不撤销已提交的事务。成功结果以数据库为准，避免将已成功操作显示为失败。本版不增加 Snackbar「撤销」操作。

无障碍：保留「更多 → 移动到分组」作为非拖动路径。首页书籍增加「与其他书籍创建分类」语义操作，弹出其他顶层书籍的选择列表，确认目标后调用相同事务；无其他书籍时禁用。开启读屏时可使用上述操作，完成及失败均播报结果。

3. 分类与数据规则

3.1 未命名分类的名称

第一次使用「未命名分类」。若已存在同名，依次尝试「未命名分类 2」「未命名分类 3」等，取当前可用的最小编号；存在该名称的空分组也算占用。不把新书合并进已有的未命名分类，每一次书籍对书籍的成功拖放都创建独立分类。

名称是普通、可重命名的分组名称，不是空字符串或特殊占位值。名称选择与插入必须在同一数据库事务中，继续保留现有分组名唯一索引。

3.2 归属与排序

  • 书籍移入分类是更新原书籍的 categoryId；bookId、EPUB 文件、封面、书签、阅读进度和后台朗读状态不变。
  • 已有分类沿用 sortOrder，新分类使用当前最大值加一，排在已有分类之后、顶层书籍之前。
  • 书籍继续按现有最近阅读时间、其次导入时间排序；拖放不修改时间戳，也不表示调整显示顺序。
  • 首页的两本书必须不同且均未分组；目标分类必须仍存在。若提交时任何前提已不成立，整次操作失败，不把已被移动的书再次强制移走。

4. 数据设计与实现建议

当前实现依据：BookshelfScreen.kt 展示分组和未分组书籍，GroupShelfScreen.kt 展示组内书籍；LibraryViewModel 负责分组和移动操作；BookRepository 与 LibraryDao 负责持久化。

CategoryEntity.name 已有唯一索引，BookEntity.categoryId 为可空外键，删除分组时设为 null。当前 LibraryDatabase 版本为 3。本功能可复用现有 schema，无需升级数据库版本。若开发中确需改 schema，另行说明原因，按项目约定优先使用 Room @AutoMigration，保留现有数据。

4.1 事务边界

操作同一 Room 事务中的步骤
移入已有分类查询并验证源书籍存在且未分组 → 验证目标分类存在 → 更新归属并确认影响 1 行 → 提交
两书新建分类验证两个 ID 不同，且书籍存在、均未分组 → 分配可用名称与 sortOrder → 插入分类 → 更新两本书归属并确认影响 2 行 → 提交

任一步失败必须回滚。不得直接串联当前的 createGroup() 与两次 moveBookToGroup() 代替原子事务。DAO 的更新方法需返回影响行数，事务内完成前置校验与结果校验。所有入口通过同一数据库写事务处理命名与归属，唯一索引冲突需作为失败处理，不能吞掉后继续移动。

4.2 状态与组件

Idle → Armed → Dragging(target?) → Committing → Idle
Armed / Dragging → Returning（无效松手）→ Idle
Armed / Dragging / Returning → Cancelled（系统或页面中断）→ Idle

  • 页面持有短期拖动状态：源 ID、主指针、起始偏移、当前位置及候选目标 ID。该状态不落库、不跨配置变化恢复。
  • 由首页公共容器统一维护网格滚动状态、可见目标矩形、命中判定及预览浮层；用同一坐标系处理定位，不用网格下标推断书籍或分组身份。
  • ViewModel 接收「书籍 → 分组」或「书籍 → 书籍」意图，只传稳定 ID；维护提交状态、拒绝重复请求，并通过现有事件通道发送成功或失败提示。
  • Repository 执行业务校验与后台 I/O，DAO 提供事务方法。自动命名规则可抽成纯函数，便于单元测试。
  • 写入成功后，由数据库观察流刷新书籍、分类和数量；合并首页数据时避免短暂出现新分类已显示但两本书仍在顶层的半成品画面。

4.3 建议修改位置

ui/BookshelfScreen.kt：手势、目标反馈、浮层和非拖动替代入口；新增独立拖拽状态/协调组件，避免页面继续堆积逻辑。ui/AppViewModels.kt：提交状态和事件；ui/SoNovelReaderApp.kt：回调接线；data/BookRepository.kt 与 data/local/LibraryDao.kt：事务化移动、自动命名和两书合并。本版不改阅读器与分组详情页手势。

6. 已确认的产品边界

  1. 范围：首版仅在首页拖动，组内移动继续使用菜单；如需组内拖出、跨分类拖动，应扩充目标呈现与导航方案。
  2. 入口：首页书籍长按改为拖动，管理操作保留在「更多」；组内长按暂不改。
  3. 命名与结果：使用「未命名分类 / 未命名分类 2 / …」，松手直接完成，不要求输入名称，不自动进入新分类。
