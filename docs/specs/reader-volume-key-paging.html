沉浸阅读音量键翻页

阅读控制栏已隐藏、没有开启语音朗读时，音量＋翻到上一页，音量－翻到下一页。 翻页后保持沉浸状态，不弹出系统音量面板，不改变系统音量。

1. 范围与默认决策

仅覆盖横向分页（PAGED）和仿真翻页（FLIP）。滚动模式（SCROLL）不支持音量键翻页，音量键交给系统默认处理。 自动生效，不增加设置项、权限、数据库字段或迁移；不改变现有触摸翻页、阅读模式和沉浸模式入口。

  • 音量＋：上一页；音量－：下一页。
  • 一次完整按压最多执行一次；长按不连续翻页。
  • 本功能将“朗读已开启”定义为 PREPARING、PLAYING、PAUSED。 暂停时会话仍可继续，因此保留音量调节；IDLE、ERROR、COMPLETED 允许音量键翻页。
  • 朗读状态以应用全局播放状态为准：即使朗读的是另一本书，也保留音量调节。

2. 当前实现依据

  • MainActivity.kt 目前没有音量键事件路由。
  • ReaderScreen.kt 以 controlsVisible 管理工具栏及状态栏； 沉浸信息栏在控制栏退出动画结束后显示。目录／书签面板和书签命名对话框有独立状态。
  • PagedReader.kt 持有 PagerState，触摸点按调用翻页动画； 通过 settledPage 和滚动结束状态回报进度及跨章。
  • FlipReader.kt 使用 PTQBookPageView；现有触摸翻页在动画完成回调中更新位置、处理跨章。
  • 两种分页阅读器使用含相邻章预览页的窗口。VerticalReader.kt 使用 LazyColumn， 已有滚动进度回报和章节边界导航。
  • TtsModels.kt 定义六种朗读状态；ReaderViewModel.kt 订阅全局播放状态，并将 PAUSED 作为可恢复朗读处理。

3. 生效条件与事件归属

开始按压时，以下条件必须全部成立：

  1. 当前页面是 PAGED 或 FLIP 阅读正文，Activity 处于 RESUMED 且窗口拥有焦点。
  2. 工具栏已完全隐藏，退出动画已结束；没有目录／书签面板、对话框、权限弹窗或其他覆盖交互层。
  3. 书籍、定位和正文有效，首次加载、章节加载、跳转及排版恢复均已结束。
  4. 全局朗读状态不属于 PREPARING、PLAYING、PAUSED。
状态新一次音量键按压
符合全部条件，阅读器空闲应用消费事件并尝试翻页。
符合条件，但触摸拖动／翻页动画正在进行消费并丢弃本次操作，不排队、不调整音量。
符合条件，但已经到达全书首尾消费事件，保持当前位置，不调整音量、不重复提示。
SCROLL 模式（含沉浸且未开启朗读）交给系统默认处理，不翻页、不滚动正文。
任一生效条件不成立交给系统默认处理，不翻页。

这里的沉浸状态由阅读控制栏状态决定；系统状态栏因边缘手势短暂浮现，不自动退出音量键翻页模式。 若系统覆盖层取得窗口焦点，则按窗口焦点规则停用。

3.1 一次按压的规则

  • 在首次 ACTION_DOWN（repeatCount 为 0）确定本次按压归属；归应用处理的按压立即尝试翻页。
  • 归应用处理的 repeat DOWN 与匹配 UP 均消费，不再次翻页；取消事件不触发操作。
  • 按压期间唤出工具栏、进入加载或启动朗读时，已归应用的按压仍只消费剩余事件， 不产生新翻页；下一次全新按压根据最新状态判断。归系统的按压中途不会被应用接管。
  • 同时按两颗音量键时，后按下的一颗不触发第二次翻页；已开始的操作不回滚。 应用不注册组合键功能；系统保留的组合键及无障碍快捷键遵循平台事件优先级。
  • 页面退出、失焦或生命周期停止时取消未执行的翻页命令并释放页面回调。 残余 UP／重复 DOWN 不得成为一次新翻页；重新获得焦点后须重新按下。
  • 只处理 VOLUME_UP 和 VOLUME_DOWN；静音键、媒体播放键及其他按键沿用现有行为。

4. 各阅读模式的翻页语义

模式一次有效操作章节边界
PAGED从当前稳定页移动一页，使用现有横向翻页动画。 章末下一页进入下一章首页；章首上一页进入上一章末页，复用相邻章窗口及现有加载逻辑。
FLIP移动一页，使用仿真翻页动画；动画完成后提交进度。 同 PAGED。不得以修改章节进度直接跳页来替代翻页动画。
SCROLL不处理音量键，保持系统音量功能。 音量键不触发滚动或跨章；原有触摸滚动及章节导航保持不变。
  • 全书首尾夹取到合法位置，不循环、不退出阅读器、不跳过空章节。
  • 跨章目标尚未缓存时发起一次现有章节加载；加载期间的新按压按第 3 节交给系统，不积攒翻页。
  • 加载失败沿用现有错误展示／提示，不能提交目标章的虚假进度；恢复后不自动补执行失败或丢弃的按键。
  • 翻页不唤出工具栏；章节标题、页码与实际展示位置同步，沿用当前阅读进度保存机制。
  • 旋转、字体调整、阅读模式切换、书签或目录跳转后，以新布局恢复完成的实际位置为起点； 旧章节、旧布局或旧书籍的命令不得继续执行。

5. 实现约束与建议

  1. Activity 统一接收硬件按键并维护按压归属。阅读页按生命周期注册、注销处理能力， 使用最新状态判断；未处理事件继续走系统默认分发。避免仅依赖 Compose 正文获得键盘焦点。
  2. 阅读页提供统一“上一页／下一页”命令与可用／忙碌状态，两种分页阅读器适配各自实际位置；滚动阅读器不注册翻页能力。 触摸与音量键共享翻页入口、边界判断和进度提交，不复制章节导航规则。
  3. 命令不持久化、不缓冲；携带或绑定书籍、章节和排版代次。 状态变化时取消旧任务，协程取消不得补写过期进度。
  4. PAGED 使用实际稳定页索引及动画状态，不用 chapterFraction 加减固定比例模拟翻页。
  5. FLIP 依赖独立 Android Library 模块 :ptqflipper，模块基于 PTQFlipper 1.1.0 适配。按键与触摸共用 CurlEngine.animateTap 及动画完成回调；通过明确的就绪、忙碌和取消接口控制翻页，不注入屏幕触摸坐标。 保留原有卷页几何与位图渲染，附带 MIT 许可，并按职责拆分以满足文件行数限制。
  6. 朗读启动请求发出至 PREPARING 发布之间也应立即停用翻页，避免异步状态空窗。 停止、失败或完成后以最新终态恢复能力。

源码位于 ptqflipper/src/main/java/ptq/mpga/ptqbookpageview/widget，来源和改动说明见 ptqflipper/UPSTREAM.txt。 app 通过项目依赖使用此库，翻页库源码及许可资源不再位于 app 模块内。

9. 独立模块边界

:ptqflipper 仅依赖 Android 与 Compose，负责卷页渲染、位图缓存、手势和动画生命周期。 对外提供 PTQBookPageView 及 PTQPageTurnController；控制器公开就绪、忙碌、翻页和取消能力。 模块不引用 app 类、书籍模型、朗读状态或音量键事件。

app 使用 FlipPageNavigation 将阅读器的导航能力接到库控制器，继续管理沉浸状态、朗读限制、 章节切换、进度与硬件按压归属。原有音量键行为和动画提交时机保持本 spec 的定义。

许可原文保留在 ptqflipper/LICENSE，并通过模块 assets 随应用打包。

拆分后验证：:ptqflipper:assembleDebug 独立产出 AAR，应用与测试 APK 编译成功， 48 项单元测试、NX888J 上 18 项设备测试再次全部通过；确认最终 APK 包含模块许可。 使用 adb install -r 覆盖安装并直接执行 instrumentation，未运行自动卸载流程。 测试前后核对原有书库、阅读进度、书签、分组记录及 755 个书籍和设置文件，数据一致。
